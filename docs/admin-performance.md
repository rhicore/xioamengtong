# 管理端图片加载优化

日期：2026-11-26。当前为本地实现和回归记录，尚未提交、发布本次优化。

## 原因与改动

此前表格显示 38×42px 缩略图，实际优先使用受保护的原图下载接口；多组列表一渲染便会加载大量 1704×2400 原图。每张图片都要经过后端登录校验、查订单、云存储下载，并在浏览器中解码。整页同时请求时，屏外图片也会占用连接。

现有列表、分页、勾选、状态、图片预览和下载流程保持原样，仅调整加载与渲染：

- `admin_web/src/OrderThumbnail.jsx` 共享加载队列。按 DOM 中从上到下、同组正面再反面启动；最多同时加载及解码 3 张。浏览器网络抵达和完成顺序可能不同，不串行等待某一张慢图。
- `IntersectionObserver` 仅将可见区域及上下 160px 内图片加入可执行队列；快速跳到下方时优先处理新区域，经过但未加载的屏外图片继续等待，不先下载整页。
- CloudBase 存储临时 URL 附加 `imageMogr2/thumbnail/80x/quality/80/format/jpg`，保留原签名。缩略处理失败时尝试原始临时链接，再尝试原有受保护的原图接口。不会改写顾客图片文件。非云存储 URL 沿用原地址。
- 20 秒无响应则尝试下一个图片来源；所有来源失败会释放队列位置，仍可点击原预览按钮。普通加载期间保留原灰色圆角图片位，异步解码完成后显示。
- 预览链接按列表顺序每批 4 单获取，第一批不等待整页链接准备完成。查询、翻页和退出时取消过期预览请求；旧响应序号保护继续保留。
- `App.jsx` 的 `OrderRows` 按订单记忆渲染，输入筛选条件、其他订单链接返回时不重绘全部分组；单张缩略图状态局部更新。
- 弹窗和下载使用原图。页面布局、CSS、本册分组和真实保存逻辑未变，无后端接口变更或新增依赖。

## 本地测量

使用真实管理端生产构建与独立测试 HTTP 服务，非线上顾客数据。20 单 × 每单 10 组 × 每组 2 图，共 400 张图片；浏览器 CPU 降速 4 倍，图片响应人为延迟 120ms，首图 800ms。原始测试 JPEG 为 2,593,448 字节，80px 测试缩略图为 5,679 字节。失败用例有意让一张缩略图失败、另一张云链接失效。

| 指标 | 改动前，1440px | 改动后，1440 / 1280 / 1024px |
| --- | --- | --- |
| 观察期首轮图片请求数 | 75 | 21 / 21 / 21，包含失败回退 |
| 图片最高同时请求数 | 6 | 3 / 3 / 3 |
| 筛选输入操作耗时 | 76ms | 34 / 30 / 36ms |
| 采样期间最大 JS 长任务 | 152ms | 59 / 61 / 62ms |

采样期为表格出现后约 1.8 秒；时间受机器负载影响，不作为线上延迟承诺。屏外不发请求是刻意的按需加载，不能把请求减少解释为图片丢失。

额外用腾讯云文档的公开示例实际请求相同处理参数：原图 158,421 字节、处理后 1,574 字节，均 HTTP 200。此项确认处理参数可用，不代表本项目生产存储权限与所有历史文件已核验。

回归覆盖图片启动顺序、并发、屏外等待、跳到末尾、失败不堵队列、原图预览、整单勾选、刷新取消；原有异步刷新回归继续验证旧响应不能覆盖新增分组，以及 ZIP 中各组图片逐字节正确。身份认证与顾客 API 测试通过。

连续整页滚动验证已通过：400 张图片全部加载，共 404 次图片请求（包含故意触发的失败回退及原图预览）；回到顶部没有重复下载。

## 后续验证与维护

- 运行方式与连续整页滚动测试见 [tests/README.md](../tests/README.md)。原有刷新回归会故意禁用网络取消，确保请求序号保护本身仍有效。
- 发布后需以实际员工会话验证临时 URL 的缩略处理可用、原图预览/下载正确；不能用本地夹具结果冒充线上测量。如果云端未支持处理，回退能保证原有访问方式，但缩略图节省的带宽需以实际返回尺寸为准。
- 改动当前不涉及后端，不需要部署后端容器；本次提交、发布按用户当前授权执行。
