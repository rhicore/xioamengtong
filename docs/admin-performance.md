# 管理端图片加载与首屏速度

维护日期：2026-11-26。初版优化 `1b85dff` 已上线，但用户确认首图变慢；当前为修复实现及对比记录，待发布后更新正式站验证结果。

## 首要要求

管理端基本是单人使用，用户要求优先实际打开速度与无明显前端卡顿。不能以固定图片并发数量、图片体积变小等指标代替首图和首屏速度。保持原有页面、分组表格、预览及下载流程。

## 已确认的问题

初版将 `previewsReady` 作为图片启动条件：订单列表已有受保护的图片地址，仍要等额外 `/order-previews` 请求，再去加载另一域名的云端处理缩略图。慢的额外接口、连接和图片处理均被串入首图关键路径；还增加了每批 4 单、最多 3 张加载及显式 `image.decode()` 等等待。

此前只测了优化版的 80px 尺寸、并发及整体滚动，没有先用旧版实测首图速度。这是验证遗漏，原“通过”不能视为用户的加载速度要求已经满足。

使用优化前 `c2f3487`、有问题的 `36664fc` 与修复工作区包接入同一正式接口比较。每轮新建浏览器会话、禁用缓存，并交替包的测试顺序；仅 HTML/JS/CSS 由各版本的本地生产构建供给，订单、登录与图片均为真实正式接口，不能将这种比较称为未经替换的正式网页测量。

复现过优化版首图 **6,735ms**，其中首次缩略图请求约 **5,952ms**；另一轮为 **5,211ms**。这些慢样本不能被云端缓存命中时较快的样本掩盖。

## 当前修复

- 删除首屏对 `previewsReady` 的依赖，列表返回后直接启动可见图片。
- 删除人为最多 3 张的限制。仅根据可见区域及上下 160px 的预取区决定是否启动；同批按页面从上到下发起，浏览器自行调度网络。
- 预览链接改为一次后台请求，不再每 4 单串行获取，且不阻塞图片。
- 图片真正开始时：已有云端链接则优先请求 80px 小图，否则直接使用原有受保护的图片地址。首屏可显示原图缩略效果，不等待云端处理。
- 背景链接到达只供尚未开始的图片使用，不能取消、重载已开始或已显示的图片。
- 保留 `decoding="async"`，加载后直接显示，不再额外等待显式 `decode()` Promise。
- 保留订单级记忆渲染、局部图片状态、翻页/查询取消过期请求和请求序号保护。弹窗及下载仍使用原图，不修改顾客文件。

## 改前与改后实测

最后两轮同接口比较（新浏览器会话、缓存禁用；静态包为本地构建）：

| 版本 | 第 1 轮首图 | 第 2 轮首图 |
| --- | --- | --- |
| 原版 `c2f3487` | 922ms | 914ms |
| 有问题的优化版 `36664fc` | 937ms | 5,211ms |
| 无人为限制、首屏立即加载的修复版 | 915ms | 917ms |

时间受网络和云端状态影响；结论是修复版不再等待预览查询和首次缩略处理，并恢复到旧版同档速度，不能宣称任意一轮都会绝对快于旧版。该两轮采样后又删除了额外的显式解码等待，发布后仍需验证真实静态页面。

## 回归验证

本地真实构建，20 单 × 10 组 × 2 图，共 400 张 1704×2400 测试图片，CPU 降速 4 倍：

- 故意挂住预览接口，首屏所有可见图片仍能显示，且不会抢先下载整页屏外图片。
- 正常采样初始图片请求约 18 个；输入响应约 39ms，最长 JS 长任务约 59ms。此处不再把并发低于 3 作为通过条件。
- 背景链接返回不会重载已显示图片；逐段滚完整页 400 张全部显示，返回顶部不重复加载。
- 检查屏外图片使用小图及失败回退、原图预览、整单勾选、刷新取消、旧响应不覆盖新分组、多组 ZIP 内容。

脚本：`tests/run-admin-performance-tests.cjs`；`ADMIN_PERF_BLOCK_PREVIEWS=1` 验证首屏不受预览接口阻塞，`ADMIN_PERF_SWEEP=1` 验证连续全页滚动。原有刷新与多组下载回归为 `tests/run-admin-refresh-tests.cjs`。

## 线上验证及后续维护

当前修复的正式域名、冷打开、重复查询、限速、整页图片与原图预览结果待发布后记录。真实页面测量脚本 `tests/run-production-admin-performance.cjs` 不再断言固定并发数或首屏必须来自处理后的 80px 图；记录真实图片来源尺寸、首图及首屏时间。

线上测试仅查询、滚动和预览，使用最小权限的临时员工账号，结束后移除账号及所属会话并查询确认；不改变顾客订单或文件。汇总记录不包含口令、Cookie、订单号及签名 URL。

后续任何性能修改必须先做原版/修改版对比，至少记录表格、第一张图片、可见区域图片、输入响应及真实请求等待链路。不能只看到省流量或请求数减少就宣称加速。
