# 订单号平台识别

顾客提交订单号时，`backend_api/src/platform.js` 会先做本地格式识别，并把结果写入订单的 `platform` 字段。识别只是辅助信息，不会调用淘宝、拼多多或京东接口，也不会因为识别失败阻止顾客上传。

当前规则：

- `6 位日期段-15 位流水号`，例如 `180902-049577984672746`：识别为拼多多，高置信度；
- `DD` 字母前缀的字母数字订单号：识别为拼多多，中置信度；
- 18 位纯数字：识别为淘宝/天猫，低置信度；
- 15-17 位纯数字：识别为京东，低置信度；
- 其他格式：不自动填写平台，保留为空。

这些规则必须视为启发式规则。平台并没有公开一个可以覆盖所有业务、地区、订单类型和历史版本的消费者订单号格式。京东官方接口只把订单号定义为字符串参数，并允许较长输入；京东官方小票规范也展示了带 `J` 平台标志的编码形式，而不是统一的普通订单号格式。拼多多官方商家资料中能看到 `180902-049577984672746` 这样的订单号示例，但示例不等于所有订单的强制规则。因此系统只在明显匹配时给出结果，无法确定时不误判。

后续如果要做到 100% 准确，需要顾客额外选择平台，或接入对应平台的授权订单接口；当前项目按需求保持无外部平台通信。

参考资料：

- [京东运营商接口文档](https://opendoc.jd.com/isp_all/api/dedicated/README5.html)：订单号作为字符串参数传递，接口没有给出一个覆盖所有订单类型的固定消费者订单号格式。
- [京东秒送开放平台小票规范](https://opendj.jd.com/staticnew/widgets/introduce/orderPrintReceiptsRules.html)：展示了带平台标志的京东编码示例。
- [拼多多官方商家资料示例](https://t16img.yangkeduo.com/mms_static/5d6a17d06ad25adf244e7ea01b2498e7.pdf)：可以看到日期段加流水号的订单号示例；该示例不应被当作所有订单的强制格式。
