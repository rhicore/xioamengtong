# 代码逻辑

## 目录之间的依赖

```text
customer_web  ─┐
               ├─ HTTP 请求 ─> backend_api ─> CloudBase
admin_web    ──┘
```

- `customer_web` 只依赖自己的 React/Vite 依赖和 `backend_api` 的顾客接口。
- `admin_web` 只依赖自己的 React/Vite 依赖和 `backend_api` 的后台接口。
- `backend_api` 依赖 Express、CloudBase Node SDK、bcryptjs、multer、archiver；它不依赖两个前端源码。
- `docs` 和 `tests` 不参与生产运行。测试脚本通过注入内存 store 验证 API，不连接线上生产数据。

## 顾客端代码

- `customer_web/src/App.jsx`：订单号输入、类型选择、图片上传、成功页和错误提示。
- `customer_web/src/ImageEditor.jsx`：图片预览、拖动、触摸缩放、裁切结果生成。
- `customer_web/src/api.js`：顾客 API 请求、上传图片和临时 URL 处理。
- `customer_web/src/styles.css`：顾客端页面和编辑器样式。

顾客端先查询订单，再进入上传页。已有图片会由 API 返回临时 URL；用户点击图片进入编辑器，确认后只提交裁切结果。前端不保存 CloudBase fileID 以外的服务端凭据。

## 后台代码

- `admin_web/src/App.jsx`：登录、筛选、订单列表、图片预览、批量下载和账号管理。
- `admin_web/src/backend/http.js`：统一封装登录、订单、预览、下载、账号管理和 HTTP 返回值处理。
- `admin_web/src/utils/platform.js`：后台显示平台名称。
- `admin_web/src/utils/time.js`：将时间转换为刚刚、分钟前、今天、昨天等相对时间。

后台使用 HttpOnly Cookie，会话只由服务端管理。普通员工不能调用账号管理写操作，管理员可以创建、禁用、启用账号和修改其他账号密码。

## API 代码

- `backend_api/server.js`：读取环境变量、创建 CloudBase SDK 和启动 HTTP 服务。
- `backend_api/src/app.js`：Express 路由、CORS、Cookie、上传限制和认证中间件。
- `backend_api/src/customer.js`：订单查询、订单创建/更新、图片上传和临时 URL。
- `backend_api/src/orders.js`：后台筛选、图片预览和按订单生成 ZIP。
- `backend_api/src/auth.js`：密码哈希、登录会话和角色权限。
- `backend_api/src/cloudbase-store.js`：CloudBase 数据库/云存储适配层。
- `backend_api/order-core.js`：订单字段校验、默认本册类型和文件命名规则。
- `backend_api/src/platform.js`：订单号平台启发式识别。

业务模块通过 store 接口访问数据和文件，不能直接把 CloudBase SDK 暴露给浏览器。未来替换数据库或对象存储时，优先改 `cloudbase-store.js`，而不是改页面。

## 两类本册类型

- “两图”：上传正面和反面两张图。
- “一张图”：只上传正面一张图。

后端内部仍保留旧代号的读取兼容，用于处理历史订单；页面只显示中文名称。
